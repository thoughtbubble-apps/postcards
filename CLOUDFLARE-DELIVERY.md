# Cloudflare delivery

This candidate prepares the public app for Workers with static assets. Current provider inventory does not contain its production target. No storage, authentication, credentials or paid services are created. Original source history is retained.

PRs from this repository run **Build and runtime tests**, then **Deploy and verify exact SHA** at an isolated `postcards-pr-N.bsunter.workers.dev` target. Fork code is skipped before checkout; **ci-required** fails unless both jobs succeed. Pushes to master repeat the stages and deploy the production Worker. Jobs target the organization `thoughtbubble-ci-prod` runner pool and an existing repository/environment `CLOUDFLARE_API_TOKEN`, exposed only during deployment. Production executions serialize without mid-deploy cancellation. The validated build is transferred as a SHA-bound integrity manifest and artifact rather than rebuilt by the deploy job. Neither is presently available to this repository: onboarding is a delivery blocker. No new token or runner is provisioned here.

`/__version` and `x-deployed-sha` identify deployed source. Worker observability is enabled. Deployment summaries expose the preview link. `scripts/verify-deployment.mjs` checks deployed SHA and the public shell. Browser core flow acceptance and canonical-domain cutover must be recorded separately; shell health does not establish feature acceptance.

For a direct preview with existing local Wrangler OAuth: prepare the numeric PR target with `node scripts/prepare-delivery.mjs preview N`, build, then `bunx wrangler deploy`. Run `DEPLOY_URL=https://postcards-pr-N.bsunter.workers.dev node scripts/verify-deployment.mjs`. Restore the committed config afterwards.

The default-branch source remains the migration base. Existing draft PR13 contains separate performance/accessibility changes and is neither absorbed nor merged here. The legacy GitHub Pages release workflow is retired; duplicate PR/Vitest and Cypress jobs are consolidated into Cloudflare validation. Cypress now runs against the Worker with synthetic card/link round trips; its configuration is updated for current Cypress. Lighthouse retains its original recommended assertions as a mandatory named stage in the same workflow. Both deployment and `ci-required` depend on that stage; a failing or skipped Lighthouse stage cannot produce aggregate success. No assertion thresholds are relaxed. Existing default-branch performance issues can therefore continue to block that check; PR13 remains the separate source remedy.

Local results: frozen install, TypeScript/production build, existing Vitest test, three Worker tests and two Cypress light/dark edit/share/receive round trips pass. The unchanged Lighthouse assertions fail on default-branch source; see separate PR13 for its existing source remedy. No score threshold or error assertion is removed.
